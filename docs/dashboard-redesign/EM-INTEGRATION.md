## 0. Ground rules

| Rule | Detail |
|------|--------|
| **Namespace** | All v2 UI lives under `dashboard/web/src/v2/`. Do not rewrite v1 components in place until the shell PR lands. |
| **Contracts first** | Specialist **S9** lands `v2/types/contracts.ts` before any component PR merges. Others import from there only. |
| **No blue accent** | Remove `#3b82f6` / indigo gradients from v2 surfaces. Accent = electric violet (`#a78bfa`). |
| **Tailwind** | Use CSS variables from `index.css` via `@theme` mapping; avoid hard-coded hex in TSX except Storybook/fixtures. |
| **Styling** | Prefer CSS modules or `className` + design tokens; no new UI framework. Keep `@tanstack/react-virtual` for long lists. |
| **App.tsx** | Only **S2** touches `App.tsx` for the v2 feature flag / route switch in the final integration PR. |

## 4. API gaps and stub strategy

### 4.1 What exists today

| Capability | Source | Notes |
|------------|--------|-------|
| Run start/stop | `POST /api/runs`, `POST /api/runs/{id}/stop` | No pause, no per-worker kill |
| SSE run events | `GET /api/runs/{id}/events` | `stage_progress`, `stage_start/end`, logs |
| Stage progress payload | `stage_progress` event | Stage-level counts only; **no sub-step** |
| Stats | `GET /api/stats` | `pipeline`, `extra` bag |
| Jobs list | `GET /api/jobs` | No "queue order" for apply |
| Applications | `GET /api/applications` | Includes `verification_confidence`, `submitted_unverified` |
| Workers count | Start run body `workers` | **No live worker telemetry** |

`apply` is **not** in `STAGE_ORDER` for `applypilot run`; apply is a separate CLI flow. UI must not assume apply appears in pipeline stage events unless backend adds it.

### 4.2 Missing for v2 (backend / SSE)

| Gap | Req # | Needed shape | Priority |
|-----|-------|--------------|----------|
| **Worker telemetry** | A.1, A.5 | `GET /api/apply/workers` or SSE `worker_progress` with `{ worker_id, job_url, title, ats, sub_step, elapsed_ms, cost_usd, state, screenshot_url? }` | P0 for real Now panel |
| **Sub-step strings** | A.1 | `sub_step` on worker events or parsed from apply log tail | P0 |
| **Timeline feed** | A.3 | `GET /api/timeline?minutes=30` → ordered events with `phase`, `ts`, `summary` | P1 |
| **Spend accounting** | A.6, B.14, D.27 | `GET /api/spend/today` → `{ applies, apply_cap, usd, usd_cap, projected_month }` | P1 |
| **Caps enforcement** | B.14 | `PATCH /api/settings/caps` + server-side stop | P2 |
| **Pause / resume apply** | B.7, B.13 | `POST /api/apply/pause`, `resume`, `kill-worker/{id}` | P2 |
| **Run plan preview** | B.9–10 | `POST /api/runs/preview` → plan + estimates | P2 |
| **Form snapshot stream** | A.1, E.29 | SSE field-level snapshot during apply | P2 |
| **Sites / warmers** | B.12, D.25 | `GET /api/sites` per ATS status | P2 (Sites page) |
| **Prompt preview** | E.28 | `GET /api/jobs/{url}/apply-prompt` | P2 |
| **Bulk re-verify** | E.31 | `POST /api/applications/reverify` | P2 |

### 4.3 v1 UI stub strategy (until APIs land)

Implement in **`v2/api/adapters.ts`** (S9). All stubs behind `import.meta.env.VITE_DASHBOARD_V2_MOCK === "true"` or automatic fallback when worker endpoint 404s.

| UI surface | Stub source | Behavior |
|------------|-------------|----------|
| **Worker chips** | `v2/fixtures/workers.json` + optional override from log regex | 1–3 workers; when SSE message matches `\[worker-(\d+)\]`, update that worker's `subStep` |
| **Now headline** | Latest `RunEvent` with `stage_progress` or log line containing "Worker" | `headline` = `event.message` |
| **Timeline ribbon** | Derive from last N `RunEvent`s (`stage_start`, `stage_end`, `stage_error`) | Map stage → phase color; compress into 30-min window |
| **Header spend** | `localStorage` keys `ap_apply_cap`, `ap_spend_cap` + manual increment on `stats_tick` | Show caps from settings; spend `$0.00` until API exists |
| **Header applies today** | `stats.applied` + count `applications` where `applied_at` is today | `needs-check` = filter `submitted_unverified` |
| **Queue order** | `fetchJobs({ pipeline_stage: "ready", sort: "activity_desc" })` | Top 10 as queue; `isNext` = index 0 |
| **Form snapshot** | `fetchApplicationDetail` → `parsed.fields` when worker active | Poll every 5s while apply running (heuristic: no `apply` stage in run → poll if any `apply_status` in progress) |
| **Pause banner** | Scan events/logs for `pause_for_human` or `RESULT_JSON` status | Show `PauseForHumanBanner` with fixture screenshot |
| **Ghost counter** | `applications.filter(s => s === 'submitted_unverified').length` | Surface in header counter `attention: true` |

Document stub usage in component Storybook/fixture pages only; production path must log once: `console.info('[v2] worker telemetry stubbed')`.

### 4.4 SSE events to handle (S9 `useRunTelemetry`)

|--------------|----------|

| `stats_tick` | S4 counters, S7 queue refresh |
| `run_finished` | S4 stop state, invalidate queries |
